## 二、三个高信号结论

### 1. 「工具/编辑器开发」被写进了 2 份 JD 的正式职责里

深圳那份写"参与项目所需工具、编辑器的维护与优化"，成都那份写"工具的设计和维护"。

**这说明它不是小众加分项，而是实习生真的会被派去做的事。** 绝大多数候选人都只会做玩法，你能自己写一个 Editor 窗口，面试时是明显的差异化。→ 项目二就做「关卡路径编辑器」。

### 2. 没有一份 JD 要求"精通所有 API"

要求全是「熟悉基本操作」「了解常用组件」「扎实的 C# 基础」。翻译过来就是：

- 不考你背得出多少 API
- 考你能不能**独立把功能做出来**，并且**说得清为什么这么写**

所以你现在的焦虑方向（"很多 API 不认识"）并不是面试真正卡的点。真正卡的是"没做过完整的东西"。

### 3. 「有个人 Demo」出现在 4/5 份 JD 里，且多处注明"优先考虑"

有的 JD 明确写"有阅读开源项目或插件源码的习惯者优先""GitHub 上有持续更新的技术项目"。

**这直接决定策略：这 10 周的核心产出是「一个讲得出细节的项目 + 可查的提交记录」，不是「学完多少课」。**

## 三、明确不要现在学（写在这防止你跑偏）

| 内容 | 为什么先不学 |
|---|---|
| DOTS / ECS | 只在少数大厂重度项目用，实习面试不考 |
| 手写 Shader | 加分项里排最后，收益远低于把玩法做扎实 |
| 网络同步 / 帧同步 | 需要项目载体，现在学了无法验证 |
| Lua / ILRuntime 热更 | 1/5 提到，且是"了解"，进公司三天能上手 |
| 复杂的 23 种设计模式 | 单例 + 观察者 + 状态机覆盖实习 90% 场景 |

## 五、面试会怎么问（提前知道，写代码时就知道该埋什么）

1. **项目深挖**：「你这个对象池什么时候扩容？池子里的对象状态怎么重置？」「为什么用事件而不用直接引用？」
2. **基础原理**：「协程是怎么实现的？」「值类型和引用类型的区别，什么时候会装箱？」「为什么 Update 里 new 会卡？」
3. **手写小题**：写个线程安全单例、写个对象池、判断一个目标在不在扇形视野内。

> 每一行代码写下去时，问自己一句"如果面试官问为什么这么写，我答得出来吗"。答不出来，就说明这段是抄的。

## 二、踩过的坑（面试最爱问这一类）

### 编译类

**1. 类名和文件名不一致，组件加不上**
在 Project 面板把 `NewBehaviourScript.cs` 改名成 `Mover.cs`，文件里的类还叫 `NewBehaviourScript`。
Unity 靠**类名**匹配脚本，不是文件名。正确做法：在 Project 面板按 F2 改名，或对类名按 F2 让 IDE 连文件名一起改。

**2. `using System.Diagnostics;` 导致 `Debug` 报红**
`.NET` 的 `System.Diagnostics.Debug` 和 `UnityEngine.Debug` 撞名，报 CS0104 歧义。
教训：**using 不是越多越好**，自动补全加的陌生 using 要删掉；真需要两个同名类型时用别名 `using Debug = UnityEngine.Debug;`。

### 逻辑思维类（这一类才是最值钱的）

**3. `while` 条件写反，一次都没进去**
判断"到没到终点"用 `Distance(...) < 0.05`，但站在起点时离终点很远，条件为 false。
**4. `Update` 里套 `while`**
`Update` 本身就是每帧被调一次，里面再套循环等于每帧循环无数遍，编辑器直接卡死。
**5. `for` 把整条路径压成一帧**
五句话在同一帧里执行，后一句覆盖前一句，净效果只走了最后一步。
三条合起来是同一个认知：**游戏是"每帧做一小步"，不是"一次做完"**。跨帧的东西必须放字段（`int index`），不能放循环变量。

**6. 骨架里的注释被当成代码**
给了 `// 1. 生成敌人 // 2. 赋值`，结果循环里只剩 `yield`，什么都不发生，也不报错。
教训：**不报错不等于代码在跑**，关键位置打 `Debug.Log` 定位执行到哪一行。

### Unity 机制类

**7. 预制体不能保存对场景物体的引用**
把敌人存成 Prefab 后，里面指向场景路径点的引用全部变成 None（运行时 null）。
解法：路径数据由生成方持有，实例化后用代码赋值 `enemy.waypoints = waypoints`。

**8. 脚本禁用时，Awake 仍执行，Start 不执行**
`Awake` 无条件执行，`Start` 只在启用时执行一次。`OnEnable` 每次激活都执行。
**结尾应用**：状态清零放 `OnEnable`（"我上场了"），而不是放归还方法（"我下场了"）。

**9. 协程不是线程**
`yield return` 被编译器改写成状态机（`MoveNext()` + `state` 字段），Unity 每帧判断"条件满足没"，满足才调一次 `MoveNext`。循环变量因为变成了字段才能跨帧保留。全部在主线程。

### 工具类

**10. Profiler 正在录制时看不了 Hierarchy**
提示 "Displaying of frame data disabled while recording"。必须先停录（点掉红色圆点），再选帧。

**11. 内存数字会骗人**
同一段代码，`GC.GetTotalMemory` 从 28752 KB 变成 20144 KB，反而降了。编辑器里噪音太大。
教训：**验证优化看可复现的计数器**（本例：池子扩建警告次数 89 → 0），不看内存数字。

**12. Git 提交漏文件**
在 TortoiseGit 列表里只勾了场景，`.cs` 没进去。以后提交前扫一眼清单里有没有 `.cs` / `.prefab`。
另外：本机 HTTPS 访问 GitHub 不通，一律用 SSH 地址。

### 方法类

**13. 看得懂，写不出来**
不是能力问题，是缺了中间层：**数据 / 状态 / 时序**。先用中文写完这三样，代码只是翻译。
配套动作：跨时间的流程要画图，不要在脑子里模拟。

**现在能跑出什么**：200 个敌人按 0.05 秒间隔从起点出发，沿 5 个点的折线路径行走，平滑转向，到终点 1 秒后归还进池子。运行期间 `Instantiate` 次数为 0。

**关键数字**：路径总长 18.6 米 / 速度 3 → 单次行走 6.2 秒；加 1 秒停留 = 占用池子 7.2 秒；间隔 0.05 秒 → 峰值 144，实测 139。
